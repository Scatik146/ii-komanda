## Мои решения по ходу (разумное прочтение)

- «Выйдет дальше» понимаю как «ошибка элемента пойдёт дальше по большой схеме» — таблица «куда уходит X».
- «Схема побольше» — кусок строки слоя a·b + c·d по 3 бита (два умножителя и сумматор): все 4096 наборов перебираются.
- Поиск виновника в строке слоя — каждый пятый вентиль (35 чипов), чтобы счёт шёл 3 минуты.
- Пролог не понадобился: задача — счёт по схемам, Python хватило (swipl в среде нет).
- Ширины сумматоров 8–48 бит; троичное слово — наименьшее того же диапазона (21 бит ↔ 14 тритов, а не 13, как в задаче
  BitNet, где диапазон ±524 288).

## Найдено по ходу

- `kalkulyatory/izmerit.py`, `uzel_slozheniya`: граница случайных чисел 2^(n−2) включительно — сумма 2^(n−1) переполняет
  n бит; при n = 8 проверка падала. **Не правила**: правка меняет случайный ряд, и числа П.2 (среднее деления 892 и др.)
  перестают воспроизводиться. В `summatory.py` — своё слово с верной границей. Вопрос учителю — § 5.
- `algoritmy.py` ищет `model.py` по пути от текущей папки (`../arifmometr`) — работает только из своей папки.
- `itog.py`: строка «степень» в выводе печатается не на своём месте (порядок строк при повторном запуске другой), числа те же.
- Глобальная настройка `shema.NASTROJKA` остаётся от предыдущей программы: `proverka_x.py` теперь сам ставит чистый базис
  (`chistyj_bazis`), `bit_ventil` отказывает на незнакомом вентиле (замок).
