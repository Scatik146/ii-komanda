### 2. ПСИХОЛОГ

**Точки перегрузки:**
1. Тройная новизна одновременно: ДРАКОН-ГРАФ + ДРАКОН-схема + ДРАКОН-лист. На 16 лет посильно концептуально, но в 40 минут — перебор.
2. Переключение между схемой и кодом: ученик строит схему → открывает Python → возвращается к схеме («узел-в-строку»). Рабочая память в стрессе.
3. Астрономическая формула — отдельный предметный слой (долгота, поправка, синодический месяц). Если не отрепетирована, съест время.

**2 точки упрощения без потери смысла:**
1. **ДРАКОН-лист = заранее распечатанный бланк.** Ученики не чертят структуру, а заполняют поля. Снимает «новизну формата», оставляет содержательное усилие.
2. **ДРАКОН-ГРАФ на этом уроке — только как заголовок формулы (1–2 узла).** Отдельный граф формулы не строим; формулу пишем в строку расшифровки. ДРАКОН-ГРАФ вводим отдельным 15-минутным фрагментом следующего урока. Смысл «сначала модель → потом код» сохраняется через ДРАКОН-схему.

### 3. ГЕЙМДИЗАЙНЕР

**Микро-механики для этапа 5 (реализация) — мотивация строить схему ДО кода:**

1. **«Узел-в-строку»** — каждый узел схемы ↔ одна строка Python. Нет узла → нет строки. Лимит: 5 узлов = 5 строк.
2. **«Код-по-узлам»** — шаблон кода с N пропусками, каждый пропуск соответствует одному узлу схемы. Ученик заполняет пропуск по своему узлу.
3. **«Слепой перевод»** — ученик пишет код, глядя только на свою схему (учебник закрыт). Партнёр проверяет: каждой строке кода — узел схемы.
4. **«Ошибка-призрак»** — учитель даёт код с 1 ошибкой и схему без ошибки; ученик находит расхождение по схеме.
5. **«Прогон вслух»** — ученик проговаривает схему узел-за-узлом, партнёр пишет код на мини-доске; потом меняются.
6. **«Каркас-фундамент»** — учитель проверяет схему перед открытием Skulpt; без схемы нет кода.

**Лучший для 40-минутного урока: № 2 «Код-по-узлам».** Шаблон кода экономит время на синтаксис, явное соответствие «1 узел → 1 пропуск» держит фокус на смысле, легко проверить, занимает 5–7 минут. Альтернатива № 1 «Узел-в-строку» быстрее, но без шаблона часть детей сядет на синтаксис Python.

### 4. ПРОВЕРКА ФАКТОВ

**4.1. Формула времени полдня по долготе**

Заявленная автором: `T_полдня = 12 + поправка + долгота_в_часах`.

**Проверка.** Истинный полдень (верхняя кульминация Солнца) в данной точке:
- В UTC: `T_UTC = 12 − λ/15` (λ — восточная долгота в градусах).
- В поясном времени (часовой пояс n = смещение UTC в часах): `T_поясн = 12 + n − λ/15 + EoT`, где EoT — уравнение времени (±15 мин в году).
- Эквивалентно через центральный меридиан пояса λ₀ = 15·n: `T_поясн = 12 + EoT + (λ₀ − λ)/15`.

**Сопоставление с авторской формулой:**

| Слагаемое автора | Должно быть | Вердикт |
| --- | --- | --- |
| `12` | 12 | ОК |
| `поправка` | n (часовой пояс) ИЛИ EoT | Неоднозначно |
| `долгота_в_часах` | `−λ/15` ИЛИ `(λ₀ − λ)/15` | Знак и опорная точка не указаны |

**Расчёт для городов Московской области (без EoT):**

| Город | λ°E | T_полдня_MSK |
| --- | --- | --- |
| Москва | 37,617 | 12 + (45 − 37,617)/15 = 12:29:32 |
| Подольск | 37,55 | 12:29:48 |
| Балашиха | 37,96 | 12:28:10 |
| Сергиев Посад | 38,13 | 12:27:30 |
| Зарайск | 38,88 | 12:24:29 |

Второй способ (через UTC): для Москвы `12 + 3 − 37,617/15 = 15 − 2,5078 = 12,4922 = 12:29:32 MSK`. Совпадает.

**Вердикт по формуле:** упрощённая форма верна по существу, но **не до конца определена**. Ученику нужно явно сказать:
- `долгота_в_часах = (λ₀ − λ)/15`, а не просто `λ/15`;
- `поправка` = уравнение времени для даты (можно взять 0, тогда погрешность до ±15 мин — допустимо для урока).

**Источники:**
- NOAA Solar Position Calculations — gml.noaa.gov/grad/solcalc/solareqns.PDF
- Wikipedia, «Уравнение восхода» — ru.wikipedia.org/wiki/Уравнение_восхода (связь солнечного и поясного времени; 15°/час)
- Подтверждение знака: восточная долгота со знаком минус, деление на 15, прибавление номера пояса (поисковый фрагмент «Солнечные часы»)

**4.2. Время пика яркости Луны — упрощённая модель**

Пик яркости = момент полной Луны (фазовый угол ~0°; оппозиционным эффектом ~12 ч для школы пренебрегаем).

**Упрощённая модель без эфемерид:**
- Синодический месяц S = 29,5306 сут (Wikipedia, «Фазы Луны»).
- По реперной дате известного полнолуния T₀: `T_full = T₀ + k·S`, k ∈ ℤ.
- Точность: типично ±12 ч, иногда до ±1 сут (орбита эллиптична, S варьируется от 29,18 до 29,93 сут).

**Допустимый для урока уровень:** ±1 сутки (до часа). Достаточно, чтобы показать идею фазового цикла.

**Альтернатива «в уме»:** `W = L·11 − 14 + D + M`, где L — лунное число года, D — дата, M — месяц (astrogalaxy.ru). Точность — сутки.

**Источники:**
- ru.wikipedia.org/wiki/Фазы_Луны (синодический месяц = 29,5306 сут)
- astrogalaxy.ru/275.html — расчёт Луны «в уме»
- Meeus J. Astronomical Algorithms — точный алгоритм (для справки, школьникам избыточен)
