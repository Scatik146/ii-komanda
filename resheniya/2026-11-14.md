# Решения 14.11 — модели и роли (решение учителя)

Составила: Алиса (координатор), проверила: Claude. Состояние — `drakon-graf/docs/komanda/SOSTOYANIE.md`.

## Порядок работы
- Состояние составляет Алиса; в SOSTOYANIE.md вставляет учитель
  (или Claude с доступом к GitHub — как руки учителя, не как рабочий чат);
  рабочие чаты туда не пишут — только сводки («Для Алисы: …»).
- Правило вставки: Алиса готовит блок → учитель решает, кто вставляет
  (он сам или Claude) → Алиса помечает у себя «внесено».
  Если вставивший поправил блок Алисы, он ОБЯЗАН сообщить ей,
  что именно изменил (пример 14.11: Claude перенёс консилиум-план
  в «Закрыто» и указал «навыки graficheskij-konspekt и drakon-shema —
  чат сервиса, не Ч-06»).
- Нумерация: чаты — Ч-NN (Ч-02…Ч-12), задания — З-NNN (З-002…З-008).
- Отчёт координатора начинается со строк
  «Мы здесь / Следующий шаг / Нужно от учителя».
- Одна тема — один чат (правило из решения по сервису «конспект/схема по ссылке»).

## На обсуждении (не решено)
- Команда ii.py sostoyanie: скрипт отправляет сводки чатов координатору по API,
  координатор возвращает блок, скрипт сам пишет SOSTOYANIE.md — тогда состояние
  пишет только координатор, буквально.
- Канал (ответ Claude): отдельный бот не нужен — тот же ключ Yandex AI Studio.
  Модель Alice AI LLM по API не имеет памяти чата, поэтому скрипт при каждом вызове
  передаёт ей: роль координатора (промпт), текущий SOSTOYANIE.md и новые сводки.
