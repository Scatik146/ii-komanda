## 0. Сдвиг — лексемы ВХОД и ВЫХОД уровня

Вложение в блоках задаётся сдвигом на 2 пробела (Tab = 2 пробела; нечётный сдвиг — ошибка «нечётный сдвиг», `zapis.js` `preprocess`). Как отступы в Python, лексер уровня переводит последовательность строк в поток с токенами **ВХОД** (глубина выросла) и **ВЫХОД** (глубина упала):

```
глубина(i) = (число ведущих пробелов строки i) / 2 ;
между строками i-1 и i :
  глубина(i) > глубина(i-1) на k  →  ВХОД × k
  глубина(i) < глубина(i-1) на k  →  ВЫХОД × k
  глубина(i) = глубина(i-1)      →  (без токена уровня)
в начале блока — неявный ВХОД на глубину 0 ; в конце — ВЫХОД до 0
```

Так глубина задаётся явно (а не «отступ = 2, {2}», который не фиксирует уровень). Дальше грамматика блоков пишется по ВХОД/ВЫХОД.

## 1. Грамматика блока `дракон` (РБНФ)

По `zapis.js` (`DrakonZapis.razobrat`) и `drakon-zapis.md`. Лексика общая с `конспект` и `мат`: одна строка — одна икона; ключевое слово — в начале строки, строчные, `ё` = `е`, заканчивается двоеточием; у каждого слова есть английский синоним (`zapis.js` `KW`: `название/title`, `ветка/branch`, `вопрос,если/question,if`, `да/yes`, `нет/no`, `выбор/select`, `вариант/case`, `пока/while`, `делать/do`, `для/for`, `низ/end`, `ввод/input`, `вывод/output`, `комментарий/comment`). Строка без ключевого слова — Действие. `# …` — пояснение (на схему не попадает; `#` только в начале строки или после пробела — иначе часть текста). `\` в начале отменяет ключевое слово.

```
блок-дракон   = ( "```дракон" | "```drakon" ), "\n", схема, "```" ;
схема         = [ название ], ( силуэт | примитив ) ;
название      = ( "название:" | "title:" ), " ", текст ;          (* только на верхнем уровне; второе — ошибка *)
примитив      = { шаг } ;                                         (* верхний уровень без «ветка:» *)
силуэт        = { ветка } ;                                       (* верхний уровень — только «ветка:»; «конец» здесь — ошибка *)
ветка         = ( "ветка:" | "branch:" ), " ", имя-ветки, тело ;  (* шаги ниже со сдвигом *)
шаг           = действие | вопрос | выбор | цикл | ввод-вывод | комментарий | переход ;
действие      = текст ;                                           (* лист: ВХОД под ним — ошибка «лишний сдвиг» *)
вопрос        = ( "вопрос:" | "если:" | "question:" | "if:" ), " ", текст,
                ВХОД, ветка-да, ветка-нет, ВЫХОД ;                (* обе ветки обязательны; пустая ветка разрешена *)
ветка-да      = ( "да:" | "yes:" ), [ " ", шаг-в-той-строке ], тело ;
ветка-нет     = ( "нет:" | "no:" ), [ " ", шаг-в-той-строке ], тело ;
тело          = [ ВХОД, { шаг }, ВЫХОД ] ;                          (* тело может быть пустым: «нет:» без шагов zapis.js принимает — правка Марьям *)
   (* шаг-в-той-строке — любая икона, кроме вопрос/выбор/цикл; иначе «перенеси ниже со сдвигом» *)
выбор         = ( "выбор:" | "select:" ), " ", текст, ВХОД, вариант, вариант, { вариант }, ВЫХОД ;  (* ≥ 2 варианта *)
вариант       = ( "вариант:" | "case:" ), " ", имя-варианта, тело ;  (* имя уникально; шаги ниже *)
цикл          = цикл-пока | цикл-до | цикл-для ;
цикл-пока     = ( "пока:" | "while:" ), " ", текст, тело ;
цикл-до       = ( "делать:" | "do:" ), тело, ( "пока:" | "while:" ), " ", текст ;
   (* «делать:» БЕЗ текста; текст после «делать:» zapis.js молча выбрасывает — см. «Где расходится»; «пока:» — на том же уровне, без тела *)
цикл-для      = ( "для:" | "for:" ), " ", текст-для, ВХОД, { шаг | низ }, ВЫХОД ;
   (* текст-для: «for s in x» | «i от 1 до n» | «N раз» — без «for» код не получится *)
низ           = ( "низ:" | "end:" ), [ " ", текст ] ;              (* лист; необязателен; пустое «низ:» = нет; дубль — ошибка *)
ввод-вывод    = ( "ввод:" | "input:" | "вывод:" | "output:" ), " ", текст ;  (* лист; «|» внутри — не поддерживается zapis.js *)
комментарий   = ( "комментарий:" | "comment:" ), " ", текст ;     (* лист *)
переход       = "выход из цикла" | "break" | "к следующему шагу" | "continue" | "конец" | "end" ;  (* лист; «конец» — только в примитиве *)
```

**Не поддерживается** (`zapis.js` `NOPE_KW`/`NOPE_TWO`/`NOPE_MARK`, `drakon-zapis.md` § 5): `до:`/`until`, `пока нет:`/`while not:`, `одновременно:`/`parallel:`, `время:`/`time:`, `пауза:`/`pause:`, `таймер:`/`timer:`, `вставка:`/`insert:`, `полка:`/`shelf:`, адреса `→`/`-> Branch`, слияние `@имя`; метки и переходы вверх (goto), `return`, параллельные процессы, цикл ЖДАТЬ, несколько входов.

## 2. Грамматика блока `конспект` (РБНФ)

Блок общий для школьной части и режима знаний (`KOD-PO-GRAFOVSKI.md`): без `режим: знания` конспект обычный — ничего не ломается. Сдвиг — теми же ВХОД/ВЫХОД (§ 0). Опции (`graf.pl` `optkey`) — `схема`, `ширина`, `нумерация`, `класс`, `язык`, `режим`.

### 2.1. Обычный режим

Схему задаёт запись, а не название (шпаргалка `конспект`). Линии — из `parser.js`/`graf.pl` `classify`.

```
блок-конспект   = "```конспект", "\n", { строка-конспект }, "```" ;
строка-конспект = опция | заголовок-к | запоминатель | пункт | нумерованный
                | связка | пример-к | контрпример-к | стрелка-к | выноска
                | рисунок | код-строка | текст-к ;
опция           = optkey, ":", " ", значение ;                     (* optkey ∈ {схема,ширина,нумерация,класс,язык,режим} *)
заголовок-к     = "тема:", " ", текст ;                            (* «вопрос:» устарело — пишите «тема:» (parser.js) *)
запоминатель    = указатель, " -> ", ответ, [ ВХОД, { пункт | нумерованный | текст-к }, ВЫХОД ] ;  (* схема — батарея; пункты ниже *)
пункт           = ( "-" | "–" ), " ", текст ;
нумерованный    = цифры, ( "." | ")" ), " ", текст ;               (* «1. шаг» — лестница *)
связка          = "связка:", " ", часть, " | ", часть, { " | ", часть } ;  (* таблица-сравнение — шеренга *)
пример-к        = "пример:", " ", текст ;
контрпример-к   = "контрпример:", " ", текст ;
стрелка-к       = [ "двойная " ], "стрелка:", " ", текст ;         (* «почему:» устарело — пишите «стрелка:» *)
выноска         = ( "выноска" | "уточнение" | "пояснение" ), [ ( " снизу" | " справа" ) ], ":", " ", текст ;
рисунок         = "рисунок:", " ", текст ;
код-строка      = "код:", " ", текст ;                             (* блок `` `…` `` — тоже код *)
текст-к         = текст ;
```

### 2.2. Режим знаний (`режим: знания`)

Для фактов и правил (расширенная часть языка; школьнику знать не нужно). Опробовано на стенде Prolog 15.11.2026. **Пока умеет только отношения двух участников** («кто отношение кого»), без «или» и «не» (`graf.pl` § 6, упрощения пробы; см. § 4 — ПРЕДЛОЖЕНИЕ).

```
блок-знаний   = "```конспект", "\n", заголовок-к, "режим: знания", { переменная | факт | правило | пример-к | контрпример-к | запрос }, "```" ;
переменная    = имя-переменной, " -> ?", "\n" ;                    (* запоминатель с пустым ответом — объявить каждую; русские Х, У, З, Ц, Ш… *)
факт          = "связь ", участник, " -> ", участник, ": ", отношение ;
правило       = "правило: ", голова, ", если ", условие, { " и ", условие } ;
   (* голова и условия — «кто отношение кого»; условий не больше 3; несколько правил одного имени — ветки *)
запрос        = "запрос:", " ", текст ;                            (* «кто», «что», «кого»… — переменные сами по себе *)
```

## 3. Смысл режима знаний

Знания в режиме `знания` — это логическая программа без побочных эффектов: **факты** и **правила** задают отношение, **пример/контрпример** — тесты, **запрос** — цель.

- **Истинность = выводимость за конечное число шагов** (наименьшая модель языка: верно то, что из фактов и правил выводится, остальное — не выводится).
- **«не»** — отрицание по обоснованной (well-founded) семантике: `не P` истинно, когда `P` не выводится и нет оснований считать его неизвестным. В SWI-Prolog — `tnot/1`.
- **Способ вычисления — дело реализации.** Корректный способ для рекурсивных правил (особенно левой рекурсии) — **таблирование** (`:- table имя/arity.`): оно запоминает начатые цели и не зацикливается. Глубинный поиск без таблирования — временная заплатка пробы и может дать ложное «контрпример не выводится» (см. «Где расходится»).

## 4. Таблица «строка режима знаний → Пролог»

Опора — `graf.pl` § 6 (`know_text`, `add_fact`, `add_rule`, `phrase_goal`, `word_term`) и `12_ГРАФ_и_Prolog.md` § 3, § 6. Участники — постоянные (атомы в кавычках: `'12'`); переменные — заглавные латинские `A`, `B`, `C`… (порядок первой встречи в голове и теле; `portray_clause`). Каждое отношение таблируется (`:- table имя/2.`) — по смыслу § 3.

| Строка режима знаний | Пролог |
|---|---|
| `тема: Кратность` | имя модуля (`12_ГРАФ_и_Prolog.md` § 3: `тема:` → модуль) |
| `режим: знания` | включает загрузку фактов/правил и проверки (`graf.pl` `mode_warning`) |
| `Х -> ?` | объявление переменной; в правилах — заглавная латинская (A, B, C…) |
| `связь 12 -> 6: кратно` | `:- table кратно/2.` · `кратно('12', '6').` (участники — атомы-константы в кавычках; `add_fact`) |
| `правило: Х кратно З, если Х кратно У и У кратно З` | `:- table кратно/2.` · `кратно(A, B) :- кратно(A, C), кратно(C, B).` (Х→A, З→B, У→C; `add_rule`: `split_if` по «, если », « и » → конъюнкция) |
| `пример: 12 кратно 3` | тест: цель должна выводиться (`test_line`, `Want=true`, метка ✓) |
| `контрпример: 3 кратно 12` | тест: цель не должна выводиться (`test_line`, `Want=false`) |
| `запрос: что кратно 3` | цель `кратно(A, '3')`; ответы — запоминатели `что -> 6`, `что -> 12` (`query_lines`, `question_word`) |

**Пример 4.2 на стенде** (swipl-wasm, SWI-Prolog 10.1.20): листинг — ровно `кратно('12', '6').`, `кратно('6', '3').`, `кратно(A, B) :- кратно(A, C), кратно(C, B).`; проверка — пример ✓, контрпример ✓; «что кратно 3» → 6, 12. (С `:- table кратно/2.` — то же; без table — у рекурсивных правил упирается в предел шагов.)

**Связь `пример:`/`контрпример:` блока с полями `пример`/`контрпример` атома.** У атомов типов `правило` и `описание мира` есть поля `пример` и `контрпример` (`postanovka.md` § 5; проверка О13 — наличие). В блоке строки `пример:`/`контрпример:` — те же утверждения, которые гоняет движок (`test_line`). Поле атома и строка блока несут одно утверждение: поле — человеческая запись, строка блока — то, что проверяет движок. Источники требуют согласованности по смыслу, но **проверки совпадения текста поля и строки блока не описывают** — не знаю, надо проверить (см. «Что непонятно»).

## 5. ПРЕДЛОЖЕНИЕ — не действует до решения учителя

**«или» и «не» в режиме знаний.** Сейчас режим знаний понимает только отношения двух участников, без «или» и «не» (`graf.pl` § 6; шпаргалка). Предложение записи и перевода в Пролог, опирающееся на таблирование и преобразование Ллойда — Топора (дизъюнкция в теле → несколько хорновских предложений).

**«или» (дизъюнкция в теле).** Запись:
```
правило: Х соединён-с З, если Х связан-с З или З связан-с Х
```
Перевод в несколько правил с общей головой (Ллойд — Топор: `p :- (q ; r)` ⇒ `p :- q.` и `p :- r.`):
```
:- table соединён_с/2.
соединён_с(Х, З) :- связан_с(Х, З).
соединён_с(Х, З) :- связан_с(З, Х).
```

**«не» (отрицание в теле) — через `tnot` с оградой, связывающей переменные.** Запись:
```
правило: Х отдельный-от З, если не Х соединён-с З
```
Перевод (`tnot` — обоснованная семантика; ограда `узел(Х), узел(З)` связывает обе переменные, иначе `tnot` по незакреплённой переменной недопустимо):
```
:- table отдельный_от/2, соединён_с/2.
отдельный_от(Х, З) :- узел(Х), узел(З), tnot(соединён_с(Х, З)).
```
Одной строкой: **«`\+` без ограды — нельзя»** (negation as failure по незакреплённой переменной некорректно; нужна ограда, перечисляющая область, и `tnot` над таблируемым отношением).

**Обратный сбор в одну строку.** Несколько правил с одинаковой головой → одна строка `правило: …, если … или …` (условия соединяются « или »). Правило с `tnot(цель)` в теле → `…, если не цель`. Сборку делать по голове: правила с равными головами сливаются «или»; `tnot` восстанавливается как «не». Однозначность туда-обратно для произвольной смеси «или»/«не»/«и» — открытый вопрос; предложение покрывает плоский случай (тело из конъюнкции литералов, дизъюнкции и одного отрицания под оградой).

**Падежи и морфология** — открытый вопрос языка (`12_ГРАФ_и_Prolog.md` § 6): сейчас `graf.pl` сводит падежи сравнением основ (`stem`, `Анны ~ Анна`). В предложение не входит.
