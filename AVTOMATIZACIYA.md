# Автоматизация работы команды — план (13.11.2026)

**Метрика одна:** сколько минут вечера автоматизация возвращает учителю. Порог из алгоритма уроков: копирование дольше 30–40 минут в день — автоматизировать.

## Кто что делает
- **Учитель:** заявка, круги «своё», «Решения автора», приёмка, ретелл, ФГОС-номера, ПДн. Последнее слово.
- **Алиса** (чат, режим эксперта) — координатор и соавтор идеи урока: поиск, три варианта, круги «своё», со-анализ экспертизы, страж. Записи состояния ведёт только она (через учителя или workflow).
- **GLM** — экспертиза и рецензия (обычно 1–2 итерации, до 3).
- **DeepSeek** — канва, код, приложения (строгий по виду, мало ошибок). Через API.
- **Qwen** — контент, тексты, печатные. **Alice AI LLM** (Yandex AI Studio) — сводки, журнал, русский голос консилиума.
- **Claude** — архитектура и сложные приложения, пока доступен; без него — консилиум (Китай, США, Россия), решает учитель.

## Инструмент: один скрипт `tools/ii.py`
- Python, только стандартная библиотека. Запуск на ноутбуке учителя (Windows) и в GitHub Actions.
- Все модели — через OpenAI-совместимые API: DeepSeek, Yandex AI Studio, GLM, Qwen; агрегатор — по желанию, не единственный путь.
- Ключи — в переменных окружения или в файле `.env`, который не попадает в git.
- На входе — папка урока или задания с файлами промптов; на выходе — файлы ответов рядом. Сбой пишется явно: «ОТВЕТ НЕРАБОЧИЙ: пусто / отказ / обрезан / ошибка сети», без имитации.
- Позже — «пульт»: страница, где видно шаг урока и кнопки «запустить», «принять», «вернуть». Поверх того же скрипта.

## Что автоматизируем (по порядку пользы)
1. **Сборка урока** (шаг, на котором учитель останавливается): артефакты собираются параллельно, каждый по своему промпту, все читают одни «Решения автора» и канву.
2. **Проверка без учителя:** окружение приложения (нет http/https/CDN, ES2018, один файл, имена латиницей, печатный fallback есть) — скриптом; страж — другая модель сверяет результат с «Решениями автора» и заявкой. Учитель видит только отмеченное.
3. **Экспертиза и со-анализ:** запрос в GLM уходит из файла, ответ ложится в файл; черновик со-анализа делает модель, Алиса и учитель читают итог.
4. **Проекты:** DeepSeek выполняет задание → PR; GLM-рецензент пишет отзыв в PR сам.
5. **Сводка для Алисы:** скрипт собирает один файл «состояние + план + задания со статусом»; ответ Алисы в фиксированном формате учитель вставляет в форму workflow «Записать итог».

## Что остаётся ручным
Круги «своё» с Алисой, решения автора, приёмка, ретелл, ФГОС-номера, ПДн. Браузер Claude — только чтение (чаты Алисы по ссылкам) и одна проверка сайта: он дорог по лимиту.
