# Устройство `tools/ii.py` (14.11.2026, чат 07)

Этап 3 из `AVTOMATIZACIYA.md`. Алгоритм — `algoritm/v9.md`, промпты — `algoritm/prompty/`. Этот файл — задание для чата 11 (код). Решения учителя 14.11 — в конце.

## 1. Главные правила

- **Один файл, Python 3, только стандартная библиотека.** Запуск — с ноутбука учителя (Windows). Это основной и пока единственный способ.
- **Скрипт не знает про GitHub.** Он работает с папкой на диске; `git push` — отдельно, руками, в любой удалённый репозиторий (GitHub или SourceCraft). GitHub Actions — позже и только как тонкая обёртка «запусти ту же команду», без своей логики.
- **Инструмент — в `ii-komanda`, уроки — в `teacher-workpad`** (`chernoviki/<урок>/`). Скрипту передают путь к папке урока.
- **Ключей в репозитории нет.** Сбой пишется явно, без имитации (v9 § 9).

## 2. Файлы

```
ii-komanda/
  tools/ii.py            скрипт
  tools/modeli.json      роли, модели, адреса, ИМЕНА переменных с ключами
  tools/.env.primer      образец: имена переменных без значений
  .gitignore             .env
  algoritm/prompty/      промпты (уже есть)
<домашняя папка учителя>/.ii-komanda.env      сами ключи (вне любого репозитория)
```

Ключи ищутся по порядку: переменные окружения → файл из переменной `II_ENV` → `~/.ii-komanda.env` → `.env` рядом со скриптом. Файл вне репозитория нужен, чтобы ключ не попал ни в GitHub, ни в SourceCraft даже по ошибке. В журнал и на экран значение ключа не выводится никогда.

Папка урока — по v9 § 10, плюс два файла скрипта: `proverka/zhurnal.md` (время, шаг, модель, круг, вердикт, токены) и `proverka/itog.md` (что показать учителю на СТОП 3).

## 3. Команды

| Команда | Что делает | Вход | Выход |
|---|---|---|---|
| `ii.py klyuchi` | пробный короткий вызов каждой модели | `modeli.json`, ключи | таблица: работает / нет ключа / нет денег / ошибка сети |
| `ii.py novyj <урок>` | создаёт папку урока с пустыми `zayavka.md`, `resheniya.md` | — | папка по v9 § 10 |
| `ii.py ekspertiza <урок>` | шаг 3: экспертиза → со-анализ | `zayavka.md`, `resheniya.md` | `ekspertiza.md`, `so-analiz.md` → **СТОП 2** |
| `ii.py sborka <урок>` | шаги 4–6: волны 1–4 | + набор артефактов из заявки | `kanva.md`, `artefakty/`, `assets/vizual.md`, `proverka/` → **СТОП 3** |
| `ii.py proverka <урок> [код]` | только проверка (окружение + страж) | готовые файлы | `proverka/<код>-strazh.md`, `itog.md` |
| `ii.py vernut <урок> <код> "что не так"` | возврат одного артефакта после приёмки | замечание учителя | новая версия + проверка |
| `ii.py kartinki <урок> [имя]` | рисует по `assets/vizual.md` (вторая очередь); с именем — перерисовать одну | `vizual.md` | `assets/*.jpg`, `assets/prosmotr.html` |
| `ii.py vydacha <урок>` | после приёмки: вшивает картинки в принятые файлы | `artefakty/`, `assets/` | `vydacha/` — файлы на урок |
| `ii.py status <урок>` | где урок: какие файлы есть, какие вердикты | папка | строки на экран |
| `ii.py zapros --rol R --prompt F --vyhod F` | один промпт в одну модель (задания, проекты) | файл | файл |

`sborka` продолжает с места остановки: готовый и принятый стражем файл заново не делается (ключ `--zanovo <код>` — переделать). Файл, положенный в `artefakty/` руками (например приложение от Claude из чата), не генерируется, а только проверяется.

## 4. Сборка по волнам (v9 § 6)

1. `kanva` (роль `kanva`) → страж, до 2 кругов. Без принятой канвы дальше не идём.
2. Параллельно (потоки `concurrent.futures`): `prilozhenie`, `prezentaciya`, `pechatnye`, `shpargalka` — что есть в наборе.
3. `vizual` (собирает блоки «КАРТИНКИ» из ответов волны 2 → `{{KARTINKI}}`) и `tehkarta`.
4. Проверка окружения + страж по каждому артефакту, до 3 кругов; `ВЕРНУТЬ` уходит исполнителю с таблицей правок без учителя.

Подстановки: `{{ZAYAVKA}}`, `{{RESHENIYA}}`, `{{KANVA}}`, `{{EKSPERTIZA}}`, `{{SO_ANALIZ}}`, `{{KARTINKI}}`, `{{SHABLON_TEHKARTY}}`, `{{KOD}}`, `{{REZULTAT}}`. Не найденная подстановка — остановка с ошибкой, а не пустая строка. Набор артефактов читается из таблицы заявки.

## 5. Вызовы моделей

Одна функция `vyzov(rol, tekst)` → `urllib`, `POST <адрес>/chat/completions`, ответ — текст и число токенов. `modeli.json`:

```json
{ "roli": { "kanva": ["deepseek", "qwen"], "prilozhenie": ["deepseek", "qwen"],
            "kontent": ["qwen", "deepseek"], "ekspertiza": ["glm", "qwen", "deepseek"],
            "strazh": ["alisa", "glm"], "so_analiz": ["alisa", "glm"] },
  "modeli": { "alisa": { "adres": "https://ai.api.cloud.yandex.net/v1",
                         "model": "gpt://{YANDEX_FOLDER_ID}/aliceai-llm",
                         "klyuch": "YANDEX_API_KEY", "zagolovki": {"OpenAI-Project": "{YANDEX_FOLDER_ID}"} },
              "deepseek": { "adres": "https://api.deepseek.com", "model": "…", "klyuch": "DEEPSEEK_API_KEY" },
              "glm": { "adres": "…", "model": "…", "klyuch": "GLM_API_KEY" },
              "qwen": { "adres": "…", "model": "…", "klyuch": "QWEN_API_KEY" },
              "claude": { "vid": "anthropic", "klyuch": "ANTHROPIC_API_KEY", "vklyuchen": false } } }
```

- Список у роли — порядок замены (v9 § 9): один повтор той же моделью, затем следующая в списке. Модель без ключа пропускается с записью в журнал.
- Адреса и имена моделей DeepSeek, GLM, Qwen чат 11 сверяет с документацией поставщика в день написания; адрес Яндекса и `aliceai-llm` сверены 14.11.
- **Запасной путь «всё через Яндекс»:** в Yandex AI Studio кроме Alice AI есть открытые модели Qwen и DeepSeek. Пока ключи Китая не оплачены, роли `kanva`, `kontent`, `ekspertiza` можно направить на них тем же ключом Яндекса — правкой `modeli.json`, без правки кода. Чат 11 проверяет список моделей командой `klyuchi`.
- **Claude** — отдельный переходник (другой формат запроса), выключен. Сложное приложение учитель делает в чате и кладёт в `artefakty/`.
- Страж не должен быть автором проверяемого. Если доступна одна модель — работаем, но в `itog.md` пометка «страж = автор, проверка слабая».
- Нерабочий ответ: пусто, отказ, обрезан (`finish_reason: length`), нет ожидаемого блока, ошибка сети → файл `ОТВЕТ НЕРАБОЧИЙ: <причина>` и запись в журнал.
- **Предел:** не больше 40 вызовов на одну `sborka` (`--predel N`). Нужен, чтобы зациклившаяся ошибка не тратила деньги; достигнут — остановка с причиной.

## 6. Проверка без учителя (v9 § 7)

**Окружение** — функция в скрипте, для `prilozhenie` и `prezentaciya`, отчёт в `proverka/<код>-okruzhenie.md`:
нет `http://`, `https://`, `//cdn`, внешних `src`/`href`/`@import`/`fetch`; один файл; имя файла латиницей; нет заглушек («TODO», «пример текста», «Lorem», «…» вместо содержания); признаки новее ES2018 (`?.`, `??`, `#поле`, `replaceAll`, `.at(`) — поиском по тексту скриптов. Ошибка окружения = `ВЕРНУТЬ` без вызова стража. В «тонком» файле (`artefakty/`) ссылки на `assets/<имя>.jpg` разрешены, и каждая должна быть в блоке «КАРТИНКИ»; файл в `vydacha/` проверяется повторно уже строго: один файл, ни одной ссылки наружу, ни одной оставшейся ссылки на `assets/`.

**Страж** — `prompty/strazh.md`, роль `strazh`. Первая строка ответа: `ПРИНЯТЬ` / `ВЕРНУТЬ` / `УЧИТЕЛЮ`; иное — нерабочий ответ. В `itog.md` попадают только `УЧИТЕЛЮ`, исчерпанные круги (с выбором: упростить / другой исполнитель / руками), пометки о слабой проверке и список картинок на просмотр.

## 7. Картинки (вторая очередь; правила — v9 § 6, решено 14.11)

- `kartinki`: по `assets/vizual.md` — YandexART (тот же ключ и каталог Яндекса), квадрат 1024×1024, JPEG, по одному варианту; скрипт не сжимает и не обрезает, предупреждает о файле тяжелее 300 КБ; собирает `assets/prosmotr.html` (картинка, имя, где стоит). Файл, уже лежащий в `assets/`, не перерисовывается.
- Отбор — учитель: оставить / положить свой файл под тем же именем / `kartinki <урок> <имя>`. Модели картинки не оценивают.
- `vydacha`: исполнители и страж работают с «тонким» файлом (ссылки на `assets/`); после приёмки скрипт заменяет ссылки на `data:` и кладёт один файл в `vydacha/`. Нет картинки — «НЕТ КАРТИНКИ: <имя>, <где стоит>», без молчаливого пропуска.
- Первая версия (чат 11) — без `kartinki`: `vydacha` работает с файлами, которые учитель положил в `assets/` руками. Формат запроса YandexART, цена и лимиты — отдельный чат, с настоящим ключом.
