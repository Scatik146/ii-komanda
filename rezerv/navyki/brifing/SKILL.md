# Брифинг — старт по одной фразе

Учитель пишет «начинаем брифинг» и ничего не ищет. Всё находит Claude. Все рабочие файлы брифинга — в ii-komanda `komanda/`.

## Старт (без вопросов учителю)
1. `add_repo` Scatik146/ii-komanda (push), затем `git clone --depth 1` в `/home/claude/ii-komanda`. Других репозиториев для брифинга не нужно.
2. Найти стартовое сообщение: самый свежий файл `komanda/brifing/*-start.md` (по дате в имени). Если за сегодня его нет — взять верхний блок «ОБНОВЛЕНО …» из `komanda/SOSTOYANIE.md` и раздел повестки из `komanda/BRIFING.md` под сегодняшней датой (только его, через grep или sed).
3. Выполнить порядок из `komanda/vstavka/claude/01-brifing.md` (это основной текст запуска; навык его не заменяет). Прочитать **только**: стартовое сообщение, верхний блок SOSTOYANIE.md, незачёркнутые пункты «В повестку» в BRIFING.md под сегодняшней датой. Журнал `komanda/README.md` — только § 5 (открытые вопросы), через sed.
4. Ответить учителю одним сообщением:
   - «Мы здесь» — 2–3 строки;
   - повестка — нумерованный список (зачёркнутое и «решено» не включать);
   - первый пункт: суть, варианты, рекомендация Claude, вопрос учителю.

## Ход
- Роли: учитель решает; **Алиса — координатор** (SOSTOYANIE.md); **Марьям (Claude) — архитектор**, главный программист; GLM — «Зануда»; DeepSeek — «молчаливый Джо».
- Концептуальный вопрос, где нужны голоса всех, — в **комнату переговоров** (навык `komnata`, ii-komanda `komnata/`), а не пересылкой ответов через учителя.
- Учитель — «глаза, руки, ноги и голос» команды: о реальном мире (оборудование, сеть, группы, он сам) сначала спросить его, ответ сохранить.
- По одному пункту. Порядок: ответы всех → общий разбор → голосование → решает учитель. Для GLM и Алисы — самодостаточный промпт с полным контекстом; все видят ответы всех.
- Решение учителя → строкой в `komanda/README.md` § 4; открытый вопрос → § 5; ход → `komanda/BRIFING.md` под датой. `SOSTOYANIE.md` не писать — его составляет Алиса (вставить блок можно по просьбе учителя).
- Регламент команды: чаты не пишут `SOSTOYANIE.md`, а присылают сводку «Для Алисы: …»; нумерация чатов Ч-NN, заданий З-NNN; отчёт координатора — «Мы здесь / Следующий шаг / Нужно от учителя»; журнал решений пишет исполнитель в том же чате до закрытия; утверждения о репозиториях, библиотеках и API — со ссылкой или путём к файлу, иначе «не знаю, надо проверить»; одна тема — один чат.
- Строка для Алисы: «Для Алисы: Марьям (архитектор), <чат или задача> — <сделано / частично / нужен ответ учителя> — <одна фраза>».
- Параллельные чаты не меняют статусы пунктов брифинга — только исполнитель темы или координатор.
- Большая тема → отдельный чат: дать учителю готовое стартовое сообщение.

## Конец
- Итог одной строкой в `komanda/BRIFING.md`, коммит, push.
- Последней строкой ответа — «Для Алисы: …».
- Новые задачи — отдельными чатами: стартовое сообщение файлом в `komanda/vstavka/den/<дата>/` и строка, какую модель взять.
- Дальше — навык `ekonomnaya-sessiya` (резерв навыков и памяти, если менялись).
