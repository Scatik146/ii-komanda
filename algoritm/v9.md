# Алгоритм разработки урока v9 (14.11.2026)

Одна канва, одни «Решения автора», ветки — по набору артефактов. Решения учителя от 14.11 — в `drakon-graf/docs/komanda/README.md`, § 4. Предыдущие версии — архив `istochniki/uroki/` (основа — линия v8.4; из v6 взяты экспертиза GLM, со-анализ, страж, протокол сбоя).

**v9 описывает цикл одного урока.** Режим дня, аукцион 22:00, бюджеты вечеров, банк, долги, типы уроков 0/Б/В/П/А и обязательный запасной печатный вариант остались в архиве (v8.4).

## 1. Схема

```
ЗАЯВКА (учитель) + НАБОР АРТЕФАКТОВ
   │
1. Поиск и 3 идеи ............................ Алиса
2. Круги «своё» .............................. учитель + Алиса
   ⏸ СТОП 1 — учитель утверждает «Решения автора»
3. Экспертиза → со-анализ .................... GLM → Алиса + учитель
   ⏸ СТОП 2 — учитель: что принято из экспертизы; правка «Решений автора»
4. Канва (всегда, полная) → страж ............ DeepSeek → Алиса
5. Сборка по набору, параллельно ............. каждый артефакт — свой промпт
6. Проверка без учителя ...................... скрипт + страж (Алиса)
   ⏸ СТОП 3 — приёмка: учитель видит только отмеченное
7. Ретелл утром .............................. учитель
8. После урока: строка «как прошло» .......... учитель → Алиса
```

Между остановками учитель не нужен: шаги 4–6 идут подряд (вручную — копированием, с `tools/ii.py` — сами).

## 2. Заявка

Файл `zayavka.md` в папке урока. Поля:

- Предмет, класс, группа (сколько учеников, особенности), дата и **время начала урока**, длительность.
- Тема и место урока в модуле (что было до, что будет после).
- Условия кабинета: техника у учеников, проектор, печать, интернет.
- Что обязательно должно быть на уроке; чего быть не должно.
- **Набор артефактов** — отметить нужное:

| Код | Артефакт | В наборе |
|---|---|---|
| `kanva` | Канва урока | всегда |
| `shpargalka` | Шпаргалка учителя на урок | всегда |
| `prilozhenie` | Приложение (один HTML-файл) | по заявке |
| `prezentaciya` | Презентация (HTML) | по заявке |
| `pechatnye` | Печатные листы, бланки | по заявке |
| `vizual` | Картинки для приложения, презентации, печатных | по заявке; в заявке — сколько и в каком стиле |
| `tehkarta` | Технологическая карта | по заявке |

Ветка урока — это строка набора, например: `kanva, shpargalka, prilozhenie, vizual`. Типов уроков нет.

## 3. «Решения автора»

Файл `resheniya.md` — то, что решил учитель и что никто из помощников не меняет. Рождается в кругах «своё», утверждается на СТОП 1, дополняется на СТОП 2. **Вставляется дословно в каждый промпт**; страж сверяет с ним каждый результат. Изменить его может только учитель.

Поля (хвост из пяти полей v8.4 плюс механика и результаты):

- **ИДЕЯ И МЕХАНИКА** — что происходит на уроке, своими словами учителя; что в механике нельзя подменять.
- **ЦЕЛИ И ПЛАНИРУЕМЫЕ РЕЗУЛЬТАТЫ** — что ученик знает и умеет к концу урока.
- **РЕШЕНИЯ** — всё, что выбрано в кругах «своё» и после экспертизы.
- **ОГРАНИЧЕНИЯ ГРУППЫ** — темп, уровень, управляемость, что не срабатывает.
- **НЕ ДЕЛАТЬ** — отвергнутые варианты и запреты.
- **ТЕРМИНЫ** — какими словами называем понятия с этим классом.
- **ДАЛЬШЕ** — что из урока понадобится на следующих.

Алиса — соавтор идеи (поиск, три варианта, круги «своё»); «своё» учителя — норма, не сбой. Запись в `resheniya.md` — только после слов учителя «утверждаю».

## 4. Экспертиза и со-анализ

Промпты `ekspertiza.md` (GLM) и `so-analiz.md` (Алиса). GLM медленный и точный — на нём экспертиза; Алиса быстрая — на ней со-анализ и страж. Обычно 1–2 итерации, не больше 3. На СТОП 2 учитель читает только итог со-анализа: «принять / отклонить / решить учителю» по каждому замечанию — и правит «Решения автора».

## 5. Канва

Нужна всегда, в полном виде, в том числе для урока, где ученики весь урок работают с приложением: канва — это порядок урока, а не описание материалов. Состав — в `prompty/kanva.md`: цели и задачи, этапы по минутам (что делает учитель, что делают ученики), ожидаемые вопросы и как на них отвечать, планируемые результаты, что делать, если результат достигнут раньше и если не достигнут.

Учитель канву не проверяет: её проверяет страж против «Решений автора» и заявки. К учителю канва попадает, только если страж поставил «УЧИТЕЛЮ».

## 6. Сборка по набору

Вход у каждого артефакта один и тот же: заявка + «Решения автора» + канва. Свой промпт — в `prompty/<код>.md`.

| Волна | Что | Исполнитель по умолчанию |
|---|---|---|
| 1 | `kanva` → страж | DeepSeek |
| 2, параллельно | `prilozhenie` | DeepSeek; сложное — Claude, пока доступен |
| | `prezentaciya`, `pechatnye`, `shpargalka` | Qwen |
| 3 | `vizual`: собирает заказы картинок из артефактов волны 2 | Алиса (промпты картинок) → генерация по API |
| | `tehkarta` | Qwen |
| 4 | страж по каждому артефакту | Алиса |

Картинки не задерживают сборку: каждый артефакт волны 2 ссылается на `assets/<имя>.png` и в конце ответа даёт блок «КАРТИНКИ» (имя файла, что изображено, где стоит). Артефакт обязан читаться и без картинок (рамка с подписью). `vizual` превращает заказы в промпты генерации с одним префиксом стиля; генерацию и вшивание картинок в приложение (один файл) делает скрипт.

Промпты модель-агностичны: исполнитель в таблице — по умолчанию, не условие.

## 7. Проверка без учителя

1. **Скрипт** (для `prilozhenie`, `prezentaciya`): нет http/https/CDN, ES2018, один файл, имена латиницей, заглушек нет («TODO», «пример текста», «…»).
2. **Страж** — `prompty/strazh.md`, Алиса (в скрипте — Alice AI LLM); страж не автор проверяемого. Сверяет с «Решениями автора», заявкой и канвой. Вердикт: `ПРИНЯТЬ` / `ВЕРНУТЬ` (исполнителю с таблицей правок) / `УЧИТЕЛЮ` (нужно решение автора).

Круги: канва — до 2, артефакт — до 3. Круги исчерпаны — к учителю с выбором: упростить / другой исполнитель / руками.

## 8. Точки остановки учителя

| Стоп | Когда | Что делает учитель |
|---|---|---|
| 1 | после кругов «своё» | утверждает «Решения автора» и набор артефактов |
| 2 | после со-анализа | решает по замечаниям экспертизы, правит «Решения автора» |
| 3 | после проверки | приёмка: смотрит отмеченное стражем, картинки, шпаргалку; «принять» или «вернуть» |

Только учитель: ретелл утром (рассказать урок по шпаргалке за 2 минуты; не получилось — правка шпаргалки, не канвы), номера ФГОС, ТБ, персональные данные. После урока — одна строка «как прошло, где ушёл от плана» Алисе; она попадает в «ДАЛЬШЕ» следующего урока модуля.

## 9. Сбой

Ответ пустой, отказ, не по теме, обрезан, ошибка сети — пишется явно: «ОТВЕТ НЕРАБОЧИЙ: <причина>», без пересказа и догадок. Один повтор тем же исполнителем, затем замена: DeepSeek ↔ Qwen, GLM → Qwen или DeepSeek (экспертиза — другая модель, не автор идеи), Алиса-страж → GLM. Claude недоступен — консилиум, решает учитель.

## 10. Папка урока

```
<урок>/
  zayavka.md  resheniya.md  ekspertiza.md  so-analiz.md  kanva.md
  artefakty/   prilozhenie.html  prezentaciya.html  pechatnye.html  shpargalka.html  tehkarta.md
  assets/      картинки и vizual.md (заказы и промпты)
  proverka/    <код>-strazh.md, отчёт скрипта
```

В промптах подстановки `{{ZAYAVKA}}`, `{{RESHENIYA}}`, `{{KANVA}}` и др. — содержимое этих файлов (вручную — вставить текст; `ii.py` — подставляет сам).
