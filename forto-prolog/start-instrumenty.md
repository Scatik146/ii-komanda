## Откуда тема (18.11, чат об оформлении ООП школы)

Для ООП понадобился документ по оформлению. Учитель спросил, можно ли описать правила оформления на Форто-Прологе и строить ДРАКОН-лист (блоки ```дракон и ```конспект) по Форто-Прологу.
Ответ: можно. По модели ДРАКОН-лист — одно из прочтений сборки, он не хранится, а строится из атомов:
- блок `конспект` в режиме знаний = прочтение Пролога (факты и правила);
- блок `дракон` = прочтение Форта (порядок действий);
- `пример:` / `контрпример:` = поле атома «Пример и контрпример».
По ходу выяснилось, каких инструментов не хватает. Для самого ООП они не нужны (там хватит скрипта на Python), поэтому выделены в этот проект.

## Что установил учитель (сводка, проверена в чате)

1. **Разложение сложных условий на простые и обратно.** Режим знаний `конспект` сейчас понимает только «и» и отношения двух участников, без «или» и «не». Пролог сам «или»/«не» умеет (несколько правил, `\+`). Разложение в Пролог — известный метод (преобразование Ллойда — Топора), это расширение существующего переводчика. Обратная сборка в связный текст — разработать.
2. **Сборщик ДРАКОН-листа (приложения, текста, иного) из словаря атомов — нет.** Есть только проверка готового листа `tools/drakon-list.mjs`. Разработать.
3. **Преобразователь ДРАКОН-листа в привычные людям форматы — частично есть.** drakon-graf рисует `конспект` в SVG; из блока `дракон` получается код (Python, КуМир, C, 1С). Нет: страницы, рисующей оба блока вместе (редактор «Живой конспект» — только ТЗ), и вывода в Word / таблицу / PDF.
4. **Разборщик текстов и программ в словарь атомов и слов — частично есть.** `ii.py analiz` (`tools/analiz.py`, `forto-prolog/srez-1/`) готовит кандидатов по урокам через разметчика DeepSeek. Для любых документов и программ — нет.
5. **Полное формальное описание языка — нет, и оно первое:** пункты 1–4 на него опираются. `FORTO-PROLOG.md` — черновик; синтаксис блоков описан шпаргалками, грамматики целиком нет. Уже есть задание 020 «описание языка» (GLM) — не выдано, ждёт решения о записи истинности по мирам.
6. **Стек — утверждён 17.11:** ядро словаря — gforth, знания — SWI-Prolog 10, руки — Python; на выходе — JS, HTML, Markdown. Ограничение: сайт на GitHub Pages статичный, сервер — только домашняя сеть. Варианты:
   - **А. Всё в браузере:** JS + SWI-Prolog в WebAssembly; слова Форта — свой малый интерпретатор в JS. Работает на сайте и без сети. Минус: gforth в браузер не идёт, Пролог в WebAssembly весит несколько мегабайт.
   - **Б. Всё на домашнем сервере:** Python + SWI-Prolog (мост Janus) + gforth (отдельной программой). Полная сила, но на публичном сайте не работает.
   - **В. Смешанный (совет Марьям):** тяжёлое (разборщик, сборщик, вывод в Word) — отдельные программы на Python + SWI + gforth; на сайте — просмотр и проверка на JS + Пролог в WebAssembly. Один код на Прологе в обоих местах.
   Самостоятельные приложения: исполняемый файл SWI-Prolog из сохранённого состояния, образы gforth, zip-приложение Python.
   **Проверить на стенде до выбора:** SWI-Prolog 10 в WebAssembly (работа, вес); Janus на Windows + WSL.
7. Порядок по решению 17.11: урок 23.11 → `ii.py` 0.3 → `ii.py komnata` → сервер. Этот проект по срокам — после них, если учитель не решит иначе.
